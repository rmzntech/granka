# Создание скилла в granka

Скилл — это папка с файлом `SKILL.md` в `~/.granka/skills/<папка>/`. Модель видит
только `name` и `description` из frontmatter, а тело читает, когда задача совпала.

## Порядок

1. Выбери короткое имя латиницей: `release-notes`, `sql-review`, `brand-voice`.
2. Создай `~/.granka/skills/<имя>/SKILL.md`.
3. Напиши frontmatter:

```
---
name: release-notes
description: Собирает release notes из git log и changelog. Используй, когда просят «что нового в версии».
---
```

4. В теле — только то, что модель не знает сама: где лежат данные, каким
   командам доверять, формат результата, чего не делать.

## Правила описания

- `description` — 1–2 предложения, с триггерами («используй, когда…»).
- Никаких общих слов вроде «помогает с кодом»: по описанию модель решает,
  загружать скилл или нет.
- Если у скилла есть вспомогательные файлы (шаблоны, примеры), клади их рядом
  и ссылайся относительным путём.

## Проверка

1. Перезапускать granka не нужно: скиллы читаются при создании сессии.
   Если только что создал — начни новый диалог.
2. Спроси то, что описано в триггере, и убедись, что ответ использует инструкции.

## Чего не делать

- Не устанавливай скиллы в системные каталоги и не трогай `node_modules`.
- Не дублируй в скилле общеизвестные вещи — это лишние токены в контексте.
