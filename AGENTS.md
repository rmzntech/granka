# granka — заметки для агента

Десктопный клиент для кодинг-агента Pi: чат, проекты, документы, аналитика.
Локальное приложение: Electron + Pi SDK, без облака и без платных API
(единственный ключ — OpenRouter от пользователя).

## Что где лежит

| Путь | Назначение |
|---|---|
| `electron/main.mjs` | окна, меню, платформенные флаги (`frame`, traffic lights) |
| `electron/ipc.mjs` | весь IPC-контракт main ↔ renderer, диалоги, уведомления |
| `electron/preload.cjs` | мост `window.granka`, `webUtils.getPathForFile` |
| `electron/agent.mjs` | сессии, конфиг `~/.granka`, проекты, ключи, статистика, компакция |
| `electron/tools.mjs` | свои инструменты: `todo_write`, `ask_user`, `web_search`, `web_fetch`, `task` |
| `electron/docs.mjs` | документы: `doc_outline/read/search/create/edit/format` (PDF, DOCX) |
| `electron/subagents.mjs` | роли подагентов и их промпты |
| `electron/prompt-template.mjs` | системный промпт приложения + версия/миграция `SYSTEM.md` |
| `electron/skills/*/SKILL.md` | встроенные скиллы (копируются в `~/.granka/skills`) |
| `renderer/index.html` | разметка главного окна, SVG-спрайт иконок Lucide |
| `renderer/app.js` | вся логика окна: чат, сессии, проекты, вложения, настройки-попапы |
| `renderer/app.css` | токены дизайна, компоненты, анимации, плотность |
| `renderer/markdown.js` | минимальный markdown (таблицы GFM, цитаты, код) |
| `renderer/select.js` | кастомные дропдауны + строки моделей (имя/цена/groups) |
| `renderer/themes.js` | 15 тем и вычисление контрастного текста на акценте |
| `renderer/fonts.css`, `renderer/fonts/` | Inter + JetBrains Mono (OFL), подключены локально |
| `renderer/settings.*` | отдельное окно настроек (7 разделов) |
| `test/` | node-тесты логики и Electron-тесты интерфейса |
| `packaging/arch/` | `PKGBUILD`, desktop-файл, launcher, install-скрипт |
| `packaging/build-arch.sh` | сборка Arch-пакета в локальный репозиторий `/srv/myapp-repo` |
| `build/` | иконки для сборки (`icons.svg` → png/ico) |
| `dist/` | готовые артефакты (`granka-<ver>-portable.exe`) |

Данные пользователя — только `~/.granka` (конфиг, сессии, скиллы, вложения,
`stats.jsonl`, `session-projects.json`). В репозиторий их не тащить.

## Как устроено (важное)

- Runtime: Electron 45, ESM в main, **classic scripts** в renderer.
- CSP строгая: `default-src 'self'; img-src 'self' data:`. Никаких инлайн-скриптов,
  инлайн-обработчиков и инлайн-стилей — они молча не выполняются.
- Иконки — только спрайт Lucide в `index.html` (`#i-<name>`), без emoji и «✓/✕».
- Чат ↔ проект связан жёстко через `~/.granka/session-projects.json`, папка — лишь
  фолбэк для старых сессий. Не возвращать фильтрацию по `cwd`.
- Системный промпт (`SYSTEM.md`) принадлежит приложению: только чтение в UI,
  версия в маркере; пользовательские правила — `AGENTS.md` (глобальные) и
  инструкции проекта.
- Модель/thinking/стиль у проекта свои: применяются в `activateProject`.
- Системный промпт — всегда английский; язык UI и ответов пользователю — русский; код, идентификаторы и коммиты — английский.

## Правила работы

- Минимум кода: стандартная библиотека, нативные возможности, существующие
  зависимости. Новую зависимость добавлять только по прямой просьбе и только
  чистый JS (нативных модулей быть не должно).
- Держать стиль проекта: токены `--bg/--text/--accent`, `--control`, `--radius-*`,
  `--dur*`; никаких «случайных» px и своих радиусов.
- Не переписывать чужие слои: правка точечная, в существующем стиле.
- Секреты не печатать и не коммитить; `auth.json` не читать вслух.
- Коммиты, пуш и релизы — только по просьбе.

## Проверки

```bash
npm test              # логика: smoke, markdown, tools, документы (без сети)
npm run test:ui       # главное окно (Electron, скрытое)
npm run test:settings # окно настроек
npm run test:theme    # тема применяется во всех окнах
npm run test:all      # всё подряд
```

После нетривиальной правки — запустить минимально достаточный тест и не
заявлять об успехе, если он не запускался. UI-правки проверять скриншотом
(`capturePage`) или тестом, а не «на глаз».

## Сборка пакетов — только по прямой команде

1. **Никогда не собирать пакеты «заодно»** при обычных правках кода.
2. Собирать **только ту платформу, которую попросили**: попросили Windows —
   собирается только `.exe`; попросили Arch — только пакет в `/srv/myapp-repo`.
   Вторую платформу «для симметрии» не трогать.
3. Версию поднимать только если об этом сказали; иначе оставить прежнюю.
4. Инструменты:
   - Arch: `./packaging/build-arch.sh` (без sudo, кладёт пакет в `/srv/myapp-repo`
     и обновляет `myapp.db`); установка — `./packaging/install-arch.sh` (нужен sudo,
     запускает пользователь).
   - Windows: `electron-builder --win portable --publish never` → `dist/*.exe`
     (нужен wine и сеть: `electron-builder` скачивает Electron/NSIS).
5. После сборки сообщать путь и размер артефакта и что именно проверено
   (запуск, содержимое `asar`, инициализация `~/.granka`), не выдавая
   непроверенное за проверенное.
